# 第一次试写，以及第二次回来怎么用

这是当前源码的待发布使用指南。npm 0.3.0 尚不含“快速试写”入口；安装说明见 [README](../README.md#安装)。

## 先准备一项真实任务

准备一个你本来就想写的场景、一个本地作品目录，以及已能正常调用模型的 dsh。先用自己能判断好坏的题材；不用为试用另写整本大纲。

例如，场景可以是：“雨夜茶馆里，主角等的人迟迟不来。掌柜看出他手里的信是假的，但不直接说破。只写双方试探，不引入新人物。”

在工作台顶部确认作品根目录。新作品可以直接指定一个已存在的文件夹；自动识别适用于已有章节和设定的目录。模型费用来自你配置的服务。

## 跑完一个小循环

1. 打开「章节」→「开新章」，写下场景、必须发生的事、不能发生的事。
2. 保持“快速试写”勾选。它固定比较两个方向，每篇目标约 500 字；模型实际输出可能偏长或偏短。取消勾选后使用作品设置的完整章节篇幅。
3. 生成方向，改掉不合意的说明，再生成候选。一次模型调用生成一篇；候选逐篇存盘，生成过程中可以停止后续篇目。
4. 点「去抽卡选段」。用 `j`/`k` 换段、`G` 赞、`B` 踩、空格取消。先标几处明确的取舍，其余可以不标。
5. 点「提炼规律」。读每条提议，只采纳能解释你取舍的规则；不要因为它措辞专业就全选。
6. 检查偏好档案。它应是可执行的写法，例如“动作后不补旁白解释动机”，不是“写得更好”。你可以编辑或删除规则。

候选还不是正式正文。合并、检查衔接、写入正文是另外的明确操作。

## 第二次使用：换一道题

在同一本作品的「开新章」中选新的章号，写一个不同场景。这样也避免重写同章同名候选。保持同一模型和相近输出篇幅，以便比较。

生成前看“本次偏好来源”；需要细查时，打开写作包的作者偏好一节。当前源码每次生成都会重新读磁盘，在本作品及对应轮次中选择最近更新且有实际内容的档案，跳过空骨架；它不会把多份规则自动合并。已有档案应连同作品目录一起保留。

判断是否继续用，优先看三个问题：

- 这一轮有没有更容易直接保留的段落？
- 连同阅读、标注、提炼的时间计算，修改负担有没有减少？
- 下次真正要写时，你会不会自己再次打开它？

若规则没有帮助，回到档案删改，再试一个新场景。工程测试不能替你回答写作质量问题，也没有“标够多少句就一定学会”的门槛。

## 常见卡点

| 现象 | 下一步 |
|---|---|
| 看不到快速试写 | 检查是否仍装着 npm 0.3.0；使用包含此改动的源码安装后重启 dsh |
| 还没认出作品目录 | 在工作台明确指定作品根；不是只填某篇文件名 |
| 找不到模型路由 | 先让 dsh 默认模型成功响应，或配置插件的 `distillProvider` / `distillModel` |
| 输出为空 | 查看提示后重试或换模型；本次不会覆盖已有候选 |
| 规则没出现在下一轮 | 核对来源路径与写作包；确认是“采纳”而非仅生成了提议 |
| 风格适合原题但不适合新题 | 删除过度具体的规则，再比较；迁移效果不是产品保证 |
